# Mastermind — продюсер выступлений

Единая точка входа. Пользователь приходит с чем угодно — от ссылки до "не знаю, что
рассказать" — и получает полный пакет для выступления на Research Mastermind.

**Пользователю не нужно знать про суб-скиллы.** Оркестратор сам решает, что вызывать.

---

## Проверка зависимостей (при первом запуске)

При первом запуске скилла — проверь, что всё установлено. Делай это молча, не спрашивая пользователя. Если чего-то нет — установи автоматически.

```bash
# Проверка Python-пакетов
python -c "import pptx" 2>/dev/null || pip install python-pptx
python -c "import comtypes" 2>/dev/null || pip install comtypes
python -c "import fontTools" 2>/dev/null || pip install fonttools
```

Если все три пакета на месте — продолжай без комментариев.
Если что-то установил — кратко сообщи: «Установил недостающие зависимости: python-pptx, comtypes».

---

## Загрузка контекста

**При каждом запуске читай:**
- `references/community-context.md` — кто аудитория, формат, тематики
- `references/presentation-archetypes.md` — 6 архетипов + общие правила тона
- `references/narratives-presentation.md` — нарративные структуры

## Файловая структура проекта

### Определение корневой папки

Claude Code всегда работает в какой-то директории (cwd). Скилл создаёт в ней папку `Masterminder/`:

```
[cwd]/Masterminder/
├── projects/
│   └── [название-проекта]/
└── _temp/                              — временные файлы (скрипты, QA-скриншоты)
```

**Пример:** если Claude Code запущен в `C:\Users\ivan\Documents`, папка проекта будет:
`C:\Users\ivan\Documents\Masterminder\projects\noisemap\`

### Структура папки проекта

Для каждого проекта создаются **две папки** — выходная (для пользователя) и рабочая (для процесса):

**Выходная папка** — то, что получает пользователь:
```
Masterminder/projects/[название-проекта]/
├── концепция.md                        — концепция + структура + Q&A
├── слайды.md                           — детальный контент слайдов
├── шпаргалка-спикера.md                — шпаргалка спикера
└── [Название]-Research-Wednesday.pptx  — готовая презентация
```

**Рабочая папка** — промежуточные артефакты пайплайна:
```
Masterminder/projects/[название-проекта]/_work/
├── досье.md                            — результат интервью (сырые данные)
├── угол-подачи.md                      — выбранный угол и нарратив
└── assets/                             — собранные материалы (скриншоты, фото)
```

Временные файлы (скрипты генерации, QA-скриншоты) → `Masterminder/_temp/`.

**Правило:** в выходной папке — только 4 файла, которые нужны спикеру. Всё остальное — в `_work/`.

## Пайплайн

### Этап 1: Разведка (тихая)

Если пользователь дал ссылку, файл, название проекта — исследуй МОЛЧА:
- WebSearch: что это, аналоги, контекст
- WebFetch: если дана страница
- Read: если даны файлы
- **Если есть пример результата проекта** (отчёт, скриншот, вывод) — прочитай/посмотри

Цель: прийти к интервью подготовленным. Не сообщай пользователю, что ты "исследуешь".

### Этап 1.5: Разведка автора (тихая)

Если пользователь дал ссылки на соцсети или профили — МОЛЧА исследуй:
- **Telegram:** @username, имя, описание профиля
- **GitHub:** проекты, языки, активность, аватарка
- **LinkedIn:** должность, компания, опыт, фото
- **Личный сайт:** портфолио, кейсы, описание
- **Любые другие ссылки:** X, Habr, Medium и т.д.

Что извлекаем:
- **Имя** (полное, как в профиле)
- **Фото** (URL аватарки, если реальное фото — использовать для слайда "Об авторе")
- **Био** (2-3 предложения для слайда из информации в профилях)
- **Контактные ссылки** (для финального слайда)

Всё найденное передай в интервью как дополнительный контекст.

### Этап 2: Интервью → вызов `mastermind-interview`

Передай суб-скиллу:
- Всё, что пользователь сказал о проекте
- Результаты разведки (если были)

Суб-скилл проведёт многоволновое интервью и вернёт структурированное досье.

### Этап 3: Поиск угла → вызов `mastermind-angle`

Передай суб-скиллу:
- Досье из интервью
- Результаты разведки

Суб-скилл найдёт интересный угол подачи и вернёт:
- Угол, название, pitch
- Архетип и нарратив
- Ценность для аудитории

**Покажи результат пользователю. Спроси: "Нравится направление? Или скорректируем?"**
Если нет — уточни и повтори этап 3.

### Этап 4: Концепция → вызов `mastermind-concept`

Передай:
- Досье + угол + архетип + нарратив

Получи: структуру выступления с тезисами для каждого слайда.

### Этап 5: Контент слайдов → вызов `mastermind-slides`

Передай:
- Концепцию + структуру

Получи: детальный контент каждого слайда + talking points.

### Этап 5.5: Подготовка контактных данных

Перед генерацией PPTX:

1. **Контактные данные** для финального слайда — Telegram, сайт, GitHub
2. **QR-код** — спроси пользователя, нужен ли

Изображения (скриншоты, фото) пользователь вставит сам после генерации.
Gamma создаст placeholder-ы на нужных слайдах — это указывается в `inputText`.

### Этап 5.7: Выбор движка генерации (ОБЯЗАТЕЛЬНО)

**Это третья точка согласования** (после угла подачи и сбора ассетов).

Через AskUserQuestion предложи пользователю выбрать режим генерации:

```
Вопрос: "Как генерируем презентацию?"

Варианты:

1. "HTML-Deck (рекомендуется для качества)"
   + HTML-first пайплайн с vision-loop валидацией
   + Дизайн извлекается из твоих референсов (PDF-брендбук, скриншоты, URL)
   + 17 overflow-safe layout-ов, без AI-slop, под референсы клиента
   + Без ограничений по слайдам, работает офлайн после установки
   + Качество близко к ручному дизайну — это флагман
   − Нужен Node 20+, Python 3.11+, Playwright (первый запуск — установка)
   − Нужен Anthropic API-ключ в .env
   − Первый прогон дольше (tokens extraction + vision-loop)

2. "Gamma Pro"
   + AI-дизайн: профессиональные макеты, автовыбор темы
   + До 60 слайдов, без водяного знака
   + Автоматическое скачивание PPTX (REST API polling)
   + Премиум AI-модели для изображений
   + Постобработка: Claude добавляет speaker notes, чистит лишние placeholder-ы
   − Нужен API-ключ Gamma (Pro $18/мес) + MCP-коннектор
   − Дизайн шаблонный, не извлекается из твоих референсов

3. "Gamma Free/Plus"
   + Тот же AI-дизайн от Gamma
   + До 10 слайдов (Free) или 20 (Plus $8/мес)
   + Постобработка: Claude добавляет speaker notes, чистит лишние placeholder-ы
   − Ручное скачивание PPTX (через браузер → Export → PPTX)
   − Водяной знак на Free-плане
   − Нужен MCP-коннектор Gamma

4. "Локально (python-pptx) — legacy"
   + Без внешних сервисов, работает офлайн
   + Без ограничений по слайдам, без водяного знака
   − Дизайн базовый, макеты примитивнее
   − Не рекомендуется — используй только если html-deck невозможен
     (нет Node/Playwright и нет возможности установить)
```

**После выбора:**

- **HTML-Deck:** проверь инфраструктуру (Node, Python, Playwright, ANTHROPIC_API_KEY).
  Если чего-то нет — дай команду для установки, не откатывайся молча на local.
  `engine = "html-deck"`. Передай в mastermind-pptx — тот делегирует на skill `mastermind-deck`.
  Попроси пользователя собрать в `projects/<name>/references/` референсы (PDF-брендбук,
  скриншоты любимых слайдов, URL конкурентов). Минимум 3 визуальных источника для качественной
  экстракции дизайн-системы.

- **Gamma Pro:** проверь MCP-коннектор (вызови `get_themes`). Если недоступен:
  > Gamma MCP-коннектор не подключён. Подключите его в настройках Claude Code
  > (Settings → MCP Servers → добавьте Gamma) и напишите, чтобы продолжить.

  Проверь наличие `GAMMA_API_KEY` в `.env`. Если нет — дай инструкцию по получению ключа.
  `engine = "gamma-pro"`. До 60 слайдов. Автоскачивание через REST API.

- **Gamma Free/Plus:** проверь MCP-коннектор. Если недоступен — та же инструкция.
  `engine = "gamma-free"`. Если слайдов > 10 (Free) или > 20 (Plus) — объединить.

- **Локально (legacy):** `engine = "local"`. Перейти к этапу 5.8 (выбор шаблона).

### Этап 5.8: Выбор шаблона (только для engine = "local")

**Только если пользователь выбрал "Без Gamma" на этапе 5.7.**

1. На основе темы/настроения проекта определи 3 наиболее подходящих шаблона
2. Запусти скрипт превью:
   ```bash
   python temp/preview-templates.py <шаблон1> <шаблон2> <шаблон3> --title "<реальный заголовок>" --subtitle "<подзаголовок>"
   ```
3. Прочитай полученные PNG через Read и покажи пользователю
4. Пользователь выбирает один — передай его в mastermind-pptx

### Этап 6: Визуальная презентация → вызов `mastermind-pptx`

Передай:
- Контент слайдов + собранные ассеты + тему/настроение
- **engine** (`html-deck`, `gamma-pro`, `gamma-free` или `local`)
- Для engine = `html-deck`: путь к папке `references/` + путь к `brief.yaml`
- Для engine = `local`: выбранный пользователем шаблон (из этапа 5.8)

Получи: PPTX-файл.

### Этап 7: Шпаргалка → вызов `mastermind-cheatsheet`

Передай:
- Контент слайдов + talking points + Q&A

Получи: компактную шпаргалку спикера.

### Этап 8: Доставка

**Папка проекта — единственное место для всех выходных файлов.**

Путь: `[cwd]/Masterminder/projects/[название-проекта]/`

Название папки — короткое, понятное, латиницей (slug проекта). Примеры:
`noisemap`, `territory-research`, `ai-code-review`.

**Выходная папка (для пользователя) — только 4 файла:**
1. **концепция.md** — концепция + структура слайдов + Q&A
2. **слайды.md** — детальный контент каждого слайда (текст, visual type, speaker notes)
3. **шпаргалка-спикера.md** — шпаргалка спикера (одностраничный план)
4. **[Название]-Research-Wednesday.pptx** — готовая презентация со speaker notes

**Рабочая папка `_work/` — промежуточные артефакты:**
- `досье.md` — результат интервью
- `угол-подачи.md` — выбранный угол и нарратив
- `assets/` — скриншоты, фото, собранные материалы

**Что НЕ сохраняем в папку проекта (ни в выходную, ни в рабочую):**
- Скрипты генерации → `Masterminder/_temp/`
- QA-скриншоты → `Masterminder/_temp/qa_[название]/`
- Промежуточные PPTX, временные файлы
- Превью шаблонов → `Masterminder/_temp/template-previews/`

**После сохранения — покажи полный абсолютный путь к выходной папке:**
```
Все файлы сохранены. Папка проекта:
C:\Users\ivan\Documents\Masterminder\projects\noisemap
```
(реальный абсолютный путь, не шаблон)

Спроси: "Хочешь что-то поправить?"

## КРИТИЧЕСКИЕ ПРАВИЛА КОНТЕНТА

### Честность
- **НЕ делай ложных сравнений.** Если сравниваешь с ChatGPT/NotebookLM/другими —
  проверь факты через WebSearch. Не выдумывай цифры.
- **НЕ принижай конкурентов.** Говори: "вот что отличает наш подход", а не "у них всё плохо".
- **НЕ используй незнакомые термины без объяснения.** Если говоришь "триангуляция" — объясни
  на слайде или в речи, что это значит.

### Тон
- **Клуб по интересам, не питч инвесторам.** "Ребята, смотрите что я сделал" — не "Наш
  революционный продукт".
- **Без пафоса.** Не "на стероидах", не "революционный", не "уникальный".
- **Честно о недостатках.** Лучше самому сказать, что не работает, чем ждать вопроса.

### Слайды
- **Без сокращений, которые непонятны.** "Воспроизводимость", а не "Воспроизв."
- **Каждый слайд самодостаточен.** Человек, который зашёл на середине, должен понять слайд.
- **Текст + тезисы.** Не только буллеты. Где уместно — 2-3 предложения текста.
  Но и не стена текста — баланс.

### Speaker notes
- **Подробные.** Не 2 предложения, а полный текст того, что говорить (5-10 предложений).
- **Для волнующегося спикера.** Написаны так, что можно просто прочитать вслух — и будет
  звучать естественно.
- **Включают переходы** между слайдами.

## ОБЯЗАТЕЛЬНЫЙ ЧЕКЛИСТ: Gamma-презентация (перед доставкой)

**Выполняется ВСЕГДА перед тем, как показать PPTX пользователю.**

### Постобработка
- [ ] Шрифты установлены (`install-gamma-fonts.py`)
- [ ] Шрифты без кириллицы заменены в XML
- [ ] Speaker notes на ВСЕХ слайдах (7-12 предложений)
- [ ] Контактные данные корректны
- [ ] PPTX в правильной папке

### Визуальная верификация
- [ ] Слайды экспортированы в PNG (`verify-slides.py`)
- [ ] КАЖДЫЙ PNG прочитан через Read tool
- [ ] Нет перекрывающих друг друга элементов
- [ ] Текст читаем, нет артефактов шрифтов
- [ ] Placeholder-ы только на слайдах, где запланированы изображения
- [ ] Если найдены проблемы — исправлены и перепроверены

### Доставка
- [ ] Пользователю сообщено, на каких слайдах placeholder-ы для его изображений
- [ ] PPTX показан только после прохождения всех проверок

## Правила оркестрации

- **Не показывай пользователю имена суб-скиллов.** Для него это единый процесс.
- **Между этапами — минимум текста.** Не рассказывай, что делаешь. Делай.
- **Четыре паузы для согласования:**
  1. После Этапа 3 (угол подачи)
  2. Этап 5.5 (сбор ассетов — если нужны материалы от пользователя)
  3. Этап 5.7 (выбор движка — Gamma платный / Gamma бесплатный / без Gamma)
  4. Этап 5.8 (выбор шаблона — только если engine = local, 3 варианта с превью)
- **Если пользователь хочет переделать только часть** — перезапусти только нужный этап.

## Обработка edge cases

**"Не знаю, что рассказать":**
→ Начни с мягких вопросов. Интервью вытащит тему.

**"Мой проект слишком простой":**
→ Не бывает простых проектов, бывает неправильный угол. Этап 3 это решит.

**"Я уже знаю, о чём хочу рассказать, просто сделай презентацию":**
→ Сократи интервью до 3-4 уточняющих вопросов.

**"Мне нужно только презентацию, концепция готова":**
→ Попроси концепцию/план, иди сразу к этапу 5-6.
