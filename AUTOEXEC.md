# AUTOEXEC

> **Что это:** стартовая инструкция, которую Claude автоматически выполняет в начале каждого нового
> диалога в этом проекте. Не редактируй, если не понимаешь, что делаешь.

## Шаги при старте нового диалога

1. **Прочитай контекст в этом порядке** (5 файлов, не больше):
   - `CLAUDE.md` — правила работы в этом проекте
   - `.claude/project-knowledge/project.md` — что за проект, текущая стадия
   - `.claude/project-knowledge/architecture.md` — стек, технические решения
   - `.claude/project-knowledge/patterns.md` — соглашения, термины
   - `repository-map.md` — карта файлов проекта (если существует)

2. **Проверь состояние работы:**
   - `git status` + `git diff` → есть ли незакоммиченные изменения
   - `docs/specs/progress.md` → текущая задача (если файл существует)
   - `ROADMAP.md` → какая фаза/слайс активна (если файл существует)

3. **Сообщи пользователю короткое резюме** (1-2 предложения):
   - «Текущая стадия: X. Активная задача: Y. Готов продолжить или начать новое?»
   - Если есть незакоммиченные изменения — упомянуть в первую очередь

4. **Жди подтверждения** — не начинай работу до явного «да» или конкретной задачи.

## Чего НЕ делать на старте

- Не предлагать рефакторинги или улучшения, о которых не просили
- Не перезаписывать существующие файлы без явного подтверждения
- Не запускать долгие операции (deep research, агентов) до подтверждения цели
- Не выдумывать данные — если контекста не хватает, задавай вопросы

## Если AUTOEXEC.md устарел

Если правила в этом файле противоречат тому, что прямо сейчас просит пользователь — приоритет за пользователем. После сессии — спросить пользователя, обновить ли AUTOEXEC.md.
