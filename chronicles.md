# Хроники разработки

> **Что это:** журнал значимых событий проекта в свободной форме. Каждая запись — одна-три строки
> о том, что произошло, **с акцентом на «почему», а не «что»** (что — есть в git log).
>
> **Зачем:** питает скилл `chronicles-poster` (или ручной разбор), который раз в неделю/месяц
> собирает посты для канала «Перцептрон архитектора» из реальной активности по проекту, без
> придумывания.
>
> **Когда добавлять:** при значимом архитектурном решении (новый ADR), смене направления,
> неожиданном открытии в ходе работы, преодолении блокера, отказе от ранее принятого подхода.
> **НЕ для каждого коммита** — только для событий, которые имеют значение через месяц.

---

## Шаблон записи

```
### YYYY-MM-DD — Краткий заголовок события

Одна-три строки контекста: что было, что изменилось, почему это важно.
Опционально — ссылка на ADR, коммит или внешний материал.
```
